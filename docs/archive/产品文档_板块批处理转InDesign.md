# 1. 项目目标

a. 构建一个面向运营同学的批处理流程：仅需把待转换文档放入输入目录，即可自动生成对应板块的 InDesign 成品文件。  
b. 支持 5 个板块（当前实际为 7 个），每个板块使用独立模板与独立输入目录。  
c. 输出包含：
① 每篇文档对应的 InDesign 文件（按板块分开）  
② 处理过程导出的图片文件（统一命名规则）  
③ 运行日志（便于排错）

# 2. 目录设计

a. 总目录定义  
以 `D` 作为总工作目录（根目录），其中包含 `A`、`B`、`C` 三个子目录，并在 `D` 内输出最终 InDesign 文件。

b. 目录结构

```text
D/
├─ A_templates/                        # 文件夹A：模板库（每个板块一个子目录）
│  ├─ 板块1/
│  │  └─ *.indd                        # 且仅有 1 个模板文件
│  ├─ 板块2/
│  │  └─ *.indd
│  ├─ 板块3/
│  ├─ 板块4/
│  └─ 板块5/
├─ B_inputs/                           # 文件夹B：输入库（每个板块一个子目录）
│  ├─ 板块1/
│  │  ├─ 文档A.docx
│  │  └─ 文档B.docx
│  ├─ 板块2/
│  ├─ 板块3/
│  ├─ 板块4/
│  └─ 板块5/
├─ C_images/                           # 文件夹C：导出的图片
│  └─ （可按板块分目录，或统一平铺，见命名规则）
├─ outputs/                            # 建议新增：最终 InDesign 输出目录
│  ├─ 板块1/
│  ├─ 板块2/
│  ├─ 板块3/
│  ├─ 板块4/
│  └─ 板块5/
└─ logs/
   └─ pipeline.log
```

c. 用户操作入口  
① 用户只需要打开 `B_inputs`。  
② 按板块把 `.docx` 放进对应子目录。  
③ 运行批处理后，在 `outputs` 获取结果，在 `logs` 查看日志。

# 3. 业务规则

a. 板块识别规则  
① 板块名以 `B_inputs` 下的子目录名为准。  
② 每个板块必须在 `A_templates/板块名/` 中存在且仅存在 1 个 `.indd` 模板。  
③ 若模板缺失或多于 1 个，当前板块失败并记录日志。

b. 文档处理规则  
① `B_inputs/板块名/*.docx` 中每个文件视为一篇文章。  
② 每篇文章独立生成一个 InDesign 文件。  
③ 各文章互不影响；单篇失败不阻塞其他文章。

c. 图片导出规则  
① 所有图片导出到 `C_images`。  
② 命名：`板块名称_文档名称_序号.扩展名`。  
③ 序号从 `001` 开始递增。  
④ 图片不存在时：跳过该图片并记录日志，不中断整篇文档。

# 4. InDesign 排版规则（当前版）

a. 模板约定  
① 每个模板页中至少有一个文本原型框和一个图片原型框。  
② 原型框通过 `label` 定位（例如 `proto_text`、`proto_image`）。  
③ 段落样式、对象样式、字体等视觉样式全部由模板控制。

b. 元素生成  
① `type=text`：复制文本原型框，写入文字，宽度固定，高度自适应。  
② `type=image`：复制图片原型框，按模板尺寸放图并适配。  
③ 按输入顺序纵向排列，间距由模板配置决定。

c. 分页策略（第一版）  
① 超过 `content_bottom` 时自动新建同模板续页。  
② 具体分页优化规则（如孤行控制、图文优先级）后续再细化。

# 5. 输出与命名

a. InDesign 输出文件  
建议命名：`板块名称_文档名称.indd`。  
建议路径：`D/outputs/板块名称/板块名称_文档名称.indd`。

b. 图片输出文件  
命名：`板块名称_文档名称_序号.扩展名`。  
建议路径：`D/C_images/`（或 `D/C_images/板块名称/`）。

c. 日志输出文件  
建议路径：`D/logs/pipeline.log`。  
日志内容至少包含：开始时间、板块名、文档名、失败原因、图片跳过记录、输出路径。

# 6. 执行流程

a. 流程步骤  
① 扫描 `B_inputs` 的板块目录。  
② 为每个板块定位唯一模板文件。  
③ 逐篇读取 `.docx`，抽取文本与图片，生成结构化数据。  
④ 将结构化数据应用到该板块模板，输出 `.indd`。  
⑤ 写入图片到 `C_images`，并按规则命名。  
⑥ 写日志并汇总成功/失败数。

b. 容错策略  
① 单篇失败：记录并继续下一篇。  
② 板块模板异常：跳过该板块并继续其他板块。  
③ 图片缺失：仅跳过当前图片。

# 7. 配置建议

a. 建议保留统一配置文件（JSON）  
至少包含：
① 板块目录名列表（可选）  
② 原型框 label 约定（默认值）  
③ 间距、起始 Y、内容下边界等参数  
④ 输出路径配置

b. 推荐最小配置示例

```json
{
  "root_dir": "D",
  "templates_dir": "A_templates",
  "inputs_dir": "B_inputs",
  "images_dir": "C_images",
  "outputs_dir": "outputs",
  "logs_dir": "logs",
  "text_proto_label": "proto_text",
  "image_proto_label": "proto_image"
}
```

# 8. 待确认项

a. 5 个板块的正式目录名（将影响自动匹配）。  
b. `C_images` 是否按板块分子目录存储。  
c. 最终输出是否只要 `.indd`，是否需要同时导出 `.idml`。  
d. 若同名文档重复投放，是否覆盖旧文件或自动加时间戳。

# 9. 验收标准

a. 在 5 个板块目录均有输入文档时，批处理可完成并输出对应 `.indd` 文件。  
b. 每篇文档都能在日志中找到处理记录。  
c. 图片命名满足 `板块名称_文档名称_序号`，且无命名冲突。  
d. 任一图片缺失时流程不中断，日志可追溯。
