# 1. 目标与范围

a. 构建通用批处理系统，不限定板块数量。  
① 无论是 5 个、6 个、7 个板块，只要目录结构和模板约定正确，都可自动处理。  
② 用户仅需把待处理文档放入输入目录。  

b. 输出目标。  
① 每篇输入文档生成 1 个对应的 `.indd` 文件。  
② 所有导出图片统一输出到 `C_images`（不按板块分目录）。  
③ 提供日志与冲突提示。

# 2. 目录规范

a. 根目录 `D`。  

```text
D/
├─ A_templates/                 # 文件夹A：模板目录
│  ├─ 01_板块名A/
│  │  └─ xxx.indd               # 该板块且仅该板块模板（仅1个）
│  ├─ 02_板块名B/
│  │  └─ xxx.indd
│  └─ ...
├─ B_inputs/                    # 文件夹B：输入目录
│  ├─ 01_板块名A/
│  │  ├─ 文档1.docx
│  │  └─ 文档2.docx
│  ├─ 02_板块名B/
│  └─ ...
├─ C_images/                    # 文件夹C：图片导出目录（平铺）
├─ outputs/                     # 输出 indesign 文件
│  ├─ 01_板块名A/
│  ├─ 02_板块名B/
│  └─ ...
└─ logs/
   └─ pipeline.log
```

b. 板块识别规则。  
① 以 `B_inputs` 的子目录动态识别板块。  
② 板块目录名称建议允许前缀序号，如 `01_资讯`、`02_评测`。  
③ 每个板块必须在 `A_templates` 存在同名子目录。

# 3. 输入与输出规则

a. 输入文档。  
① 每个板块目录下可放多篇 `.docx`。  
② 每篇文档独立处理，互不阻塞。

b. 图片输出。  
① 统一导出到 `C_images`。  
② 命名规则：`板块名称_文档名称_序号.扩展名`。  
③ 序号采用 3 位补零，如 `001`、`002`。  

c. InDesign 输出。  
① 只输出 `.indd`。  
② 输出路径建议：`outputs/板块名称/板块名称_文档名称.indd`。  

# 4. 冲突与容错策略

a. 同名文档重复投放。  
① 自动为新输出文件追加时间戳。  
② 建议格式：`板块名称_文档名称_YYYYMMDD_HHMMSS.indd`。  
③ 在日志中记录冲突与最终文件名，并输出提示。

b. 图片不存在。  
① 跳过该图片，不中断整篇文档处理。  
② 记录日志：板块、文档、元素序号、原路径。

c. 模板异常。  
① 若某板块模板缺失或多于 1 个 `.indd`，该板块整体跳过。  
② 继续处理其他板块并记录错误。

# 5. 模板约定（详细）

a. 模板文件约定。  
① 每个板块目录下必须且仅能有 1 个 `.indd` 文件作为模板。  
② 模板需可直接打开且无损坏。  
③ 模板页默认使用第 1 页作为原型页（后续可扩展配置）。

b. 原型对象约定（必须）。  
① 模板页中必须存在 1 个文本原型框（用于复制生成正文文本框）。  
② 模板页中必须存在 1 个图片原型框（用于复制生成图片框）。  
③ 两个原型框都必须设置脚本标签 `label`。  
④ 默认标签建议：
- 文本原型：`proto_text`
- 图片原型：`proto_image`

c. 文本原型框要求。  
① 宽度即最终文本框固定宽度。  
② 高度可为任意初值，实际落版时自动扩高。  
③ 段落样式、字体、字距、颜色等全部在模板中预设。  
④ 如需首段/正文差异，后续可扩展多文本原型标签。

d. 图片原型框要求。  
① 尺寸即最终图片框尺寸。  
② 内容适配策略：等比填充并居中（避免拉伸变形）。  
③ 边框、圆角、透明度、效果等全部由模板预设继承。

e. 排版坐标约定。  
① `start_y`：页面起排 Y 坐标。  
② `gap_y`：相邻元素纵向间距。  
③ `content_bottom`：本页可用区域下边界，超出则分页。  
④ 单位遵循 InDesign 当前文档标尺单位。

f. 分页约定（当前版）。  
① 当下一个元素超出 `content_bottom` 时，新建同模板续页。  
② 续页继续使用同一组原型框规则。  
③ 更复杂分页策略（如图文优先级）后续再定义。

# 6. 执行流程

a. 扫描流程。  
① 扫描 `B_inputs` 板块子目录。  
② 为每个板块匹配 `A_templates` 同名目录并定位唯一模板。  
③ 遍历板块下所有 `.docx`。

b. 处理流程。  
① 提取文档文本/图片并序列化。  
② 根据模板原型框创建文本与图片元素。  
③ 执行纵向排列与分页。  
④ 导出 `.indd` 到 `outputs`。  
⑤ 导出图片到 `C_images` 并按规则命名。  
⑥ 写日志与汇总统计。

# 7. 配置建议（可选）

a. 建议保留统一配置文件，便于后续细节差异扩展。  
① 全局默认标签：`proto_text`、`proto_image`。  
② 板块级覆盖：允许某板块使用不同标签或不同 `start_y/gap_y/content_bottom`。  

b. 推荐配置结构（示例）。  
```json
{
  "text_proto_label": "proto_text",
  "image_proto_label": "proto_image",
  "start_y": 40,
  "gap_y": 12,
  "content_bottom": 820,
  "sections": {
    "01_板块名A": {
      "start_y": 36,
      "gap_y": 10
    }
  }
}
```

# 8. 验收标准

a. 任意数量板块目录都可自动识别并处理。  
b. 只要模板结构符合约定即可落版成功。  
c. `C_images` 为统一目录，命名无冲突且顺序正确。  
d. 输出仅 `.indd`，同名冲突自动加时间戳并提示。  
e. 任一文档或图片异常不会阻塞全量任务。
